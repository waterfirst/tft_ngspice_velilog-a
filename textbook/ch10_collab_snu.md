## 한 문장

이 교재의 파이프라인을 연구실 실측으로 옮길 때 가장 먼저 깨지는 것은 코드가 아니라 **정의**다. Vth 추출 규칙, 측정 지연, TFT 번호, 전류를 재는 노드가 팀마다 다르면 같은 숫자가 다른 뜻이 된다. 그래서 첫 2주는 시뮬레이션보다 **정의 대응표와 기준선 재현**에 쓴다.

## D. 히스테리시스 파라미터를 측정으로 정하는 법 (9장 연결)

9장 모델은 가역 성분을 한 줄로 넣었다: 내부 상태 `mem`이 vsg를 시정수 τ(`TAUH`)로 따라가고, `Vth`에 `KH·(mem − VREFH)`가 더해진다. 실측에서 이 두 값을 정하는 가장 단순한 순서:

```
1) 기준 read          : 약한 바이어스로 Vth(0)
2) stress 계단        : vsg를 Δ만큼 올리고 t_s 동안 유지 (t_s를 여러 값으로)
3) 빠른 read          : stress 직후 지연 t_d 뒤 Vth(t_s, t_d)
4) recovery 추적      : stress 해제 후 로그 간격으로 Vth를 계속 읽음
```

- recovery가 끝까지 돌아오는 부분 = **가역**, 남는 부분 = **비가역**(4장 열화식으로 보냄)
- 가역 진폭 / Δ → `KH`의 1차 추정
- recovery 곡선을 `A·exp(−t/τ)`로 맞추면 τ → `TAUH`
- 지연 t_d가 τ보다 길면 3)에서 이미 회복돼 **KH를 과소추정**한다. t_d를 두세 값으로 바꿔 재고 0으로 외삽한다

실제 트랩은 시정수가 하나가 아니라 **넓은 분포**다(수 µs부터 수 시간). recovery가 로그 시간축에서 직선에 가깝게 떨어지면 단일 지수 대신 늘어진 지수 `A·exp[−(t/τ)^β]`나 τ 여러 개의 합이 필요하다. 9장의 1차 모델은 "프레임 시간과 비슷한 τ가 있으면 무엇이 달라지나"를 보는 **교보재**이지 측정 모델이 아니다.

양방향 스윕 히스테리시스(정방향·역방향 Vth 차이)도 같은 정보를 준다. 스윕 속도를 바꿔 차이가 최대가 되는 속도를 찾으면 τ의 대략적인 크기를 알 수 있다.

## E. 데이터·코드 경계

| 항목 | 공개 저장소 (이 교재) | 과제 내부 |
|---|---|---|
| 합성 예제 코드·데이터 | 가능 | 가능 |
| 연구실 compact model 코드 | **배포 조건 확인 전 불가** | 합의 범위 안에서 |
| 실측 I–V, 화소 전류 | 불가 | 가능 |
| 실제 화소 넷리스트·타이밍 | 불가 | 반출 범위 합의 필요 |
| 추출 규칙·스키마 문서 | 일반화하면 가능 | 가능 |

습관: **코드는 공개 가능한 형태로, 데이터 경로는 설정 파일로 분리**한다. 비밀유지 계약은 공유의 전제일 뿐 공개 허가가 아니다.

시뮬레이터를 옮길 때(예: ngspice → 상용 시뮬레이터)는 바로 변환하지 않는다. ① 원본 환경에서 골든 테스트 통과 → ② 버전·라이선스 기록 → ③ 단일 TFT I–V 재현 → ④ 그다음 화소. 시뮬레이터 차이를 모델 오차로 오인하지 않도록 바이어스·온도·초기조건을 똑같이 둔다.

## 비유: 두 주방이 "소금 한 숟갈"로 레시피를 주고받는다

측정팀과 회로팀, 그리고 이 교재는 **서로 다른 주방**이다. 레시피(파이프라인)를 그대로 넘겨도 "소금 한 숟갈"의 숟가락 크기가 다르면 맛이 달라진다.

- "Vth" = 숟가락. 최대 gm 접선인지, 정전류 기준인지에 따라 같은 소자에서도 값이 달라진다.
- "T3" = 재료 이름. 한 주방에서는 보상 스위치, 다른 주방에서는 데이터 스위치다.
- "화소 전류" = 간 보는 시점. 프레임 평균인지 발광 구간 평균인지.

그래서 요리(시뮬레이션)보다 먼저 **숟가락을 나란히 놓고 재는 날**(0단계)이 필요하다.

## 비유가 깨지는 곳

1. 숟가락 크기 차이는 환산표 한 장으로 고쳐진다. 그러나 **측정 지연 동안 회복된 가역 성분은 사후 환산으로 복원되지 않는다.** 정보가 측정 순간에 이미 사라졌기 때문이다. 프로토콜은 데이터를 받기 **전에** 맞춰야 한다.
2. 레시피는 주방이 달라도 재료의 물리가 같다. TFT는 공정·조성이 다르면 **열화 메커니즘 자체가 다를 수 있다.** 대응표로 이름을 맞춰도 식의 형태가 맞는지는 따로 검증해야 한다.

## 그래서 뭐

1. 첫 미팅의 성공 기준은 "시뮬레이션을 보여줬다"가 아니라 **C절 7개 파일 중 기대 출력을 포함해 몇 개를 받았나**다.
2. 측정 프로토콜(특히 read 지연)은 데이터가 쌓이기 전에 합의한다. 늦으면 9장 질문에 영영 답할 수 없다.
3. 이 교재의 수치(유지율, 민감도, E1)는 합성 모델에서 나왔다. 협업 자료에서는 **방법과 검사 목록**을 넘기고, 숫자는 실측으로 다시 만든다.
