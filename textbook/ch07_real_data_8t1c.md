## 한 문장

실측으로 옮길 때는 **합성 "측정" 생성기를 실제 CSV로, "정답 회로"를 실제로 잰 화소 전류로** 바꾸고 나머지 구조(추출 → 열화식 → 회로 → 칸별 채점)는 그대로 둔다. 회로를 8T1C로 키울 때는 넷리스트에 TFT를 더하는 것보다 **그 TFT가 막으려는 현상이 모델에 들어 있는지**가 먼저다.

## A. 실측으로 옮기기

### 무엇을 바꾸고 무엇을 남기나

| 합성 예제 | 실측에서 | 비고 |
|---|---|---|
| `gen_meas.py` (정답 모델로 I–V 생성) | 측정 CSV → 같은 열 이름으로 변환 | `tft, t_h, kind, vsg, vsd, id_meas, split` + **`cell_id`, `temp_C`** 추가 |
| `FLOOR_A = 15 fA` | 여러분 장비·배선의 실제 바닥 | 오프셋 측정으로 정한다 (3장 상한 처리) |
| `truth_params.json` | **없다** | 채점 기준을 따로 만들어야 한다 ↓ |
| "정답 회로" 애노드 전류 | **테스트 화소(TEG)에서 직접 잰 전류** | 없으면 파이프라인은 검증 안 된 예측일 뿐 |
| `ROLES`의 `duty`, `vgs` | 실제 구동 파형에서 TFT별 바이어스 추출 | 5장 회로를 한 번 돌려 v(g)·v(s)·v(d)를 읽는다 |
| `ptft_fit.va` | 연구실 compact model | **외부 반출·공개 허가를 먼저 확인** |
| `pixel.py` 6T1C | 실제 토폴로지 | 아래 B, TFT 번호 대응표 필수 |
| 3000 h 블라인드 | 시간순 마지막 구간 + **학습에 안 쓴 소자** | 둘 다 남긴다 |

### ML 데이터는 "넓게" 만든다

흔한 구조(한 행 = TFT 하나):

```
cell_id  time_hr  tr   vth   log_ion  log_ioff   Current_norm
C01      250      T1   1.31  -5.2     -12.1      0.93
C01      250      T2   1.12  -5.9     -12.4      0.93     ← 같은 target 반복
...
```

문제:

- 모델이 **T1–T8의 동시 상태**를 한 번에 못 본다.
- 같은 target이 TFT 수만큼 복제된다.
- 행 단위로 무작위 분할하면 **같은 화소·같은 시간의 T1 행은 학습에, T2 행은 시험에** 들어간다 → 답을 보고 시험 보는 누수. R²가 부풀려진다.

권장 구조(한 행 = 화소 하나 × 시간 하나):

```
cell_id, temp_C, time_hr, vth_T1..vth_T8, logion_T1..logion_T8, logioff_T1..logioff_T8, Current_norm
```

R 사용자라면 `tidyr::pivot_wider(names_from = tr, values_from = c(vth, log_ion, log_ioff))` 한 번이다. 6장의 X(253열)도 이 구조다.

### 검증은 세 가지를 따로 보고한다

| 이름 | 나누는 법 | 답하는 질문 |
|---|---|---|
| 보간 | 같은 조건 범위, 무작위 (단 **cell 단위로**) | 측정한 조건 안에서 얼마나 맞나 |
| 새 소자 | `GroupKFold(groups=cell_id)` | 처음 보는 화소·TEG에도 통하나 |
| 미래 시간 | 앞 시간으로 학습, 뒤 시간으로 시험 | 수명 예측에 쓸 수 있나 |

트리 계열(RF, GBM)은 세 번째에 구조적으로 약하다 (6장). `time_hr`가 학습 최대값을 넘는 RF 예측을 수명으로 쓰지 않는다.

### 실측에서 새로 만나는 것들

**온도 가속.** 70·85 °C 데이터를 섞을 때는 Arrhenius 기본형부터:

```
τ(T) = τ(T_ref) · exp[ (Ea/kB) · (1/T − 1/T_ref) ]      T는 반드시 켈빈: 70 °C = 343.15 K, 85 °C = 358.15 K
```

**전류가 올라가는 구간.** 250 h 뒤 전류가 증가했다고 이상치로 지우지 않는다. 감소·증가 두 메커니즘 최소모델로 먼저 비교한다:

```
I_norm(t) = 1 − A_d·[1 − e^−(t/τ_d)^β_d] + A_c·[1 − e^−(t/τ_c)^β_c]
```

이 식은 원인을 증명하지 않는다. 증가를 지우지 않고 **가설을 나눠 담는 그릇**이다.

**수명 정의.** `t_I90 = I_norm이 처음 0.90 이하가 되는 시간`. 전류가 비단조일 수 있으므로 **최초 도달**과 **지속 도달**(이후 계속 0.90 이하)을 구분하고, 부트스트랩으로 신뢰구간을 붙인다.

**데이터 경계.** 산학 과제 데이터·사내 netlist·PDK·모델카드는 이 교재처럼 **공개 저장소에 올리지 않는다.** NDA는 공유의 전제일 뿐 공개 허가가 아니다. 코드는 공개하고 데이터 경로만 설정 파일로 분리하는 습관을 들인다.

## B. 8T1C로 키우기

### 먼저: TFT 번호는 회로마다 다르다

논문·회사·연구실마다 "T3"가 데이터 스위치이기도 하고 보상 스위치이기도 하다. 숫자를 맞추지 말고 **기능 대응표**를 먼저 만든다.

| 이 교재 | 기능 | 여러분 회로 번호 | 비고 |
|---|---|---|---|
| T1 | 구동 | | |
| T2 | 데이터 기록 스위치 | | |
| T3 | 문턱 보상 (다이오드 연결) | | IGZO? |
| T4 | 게이트 초기화 | | IGZO? |
| T5 / T6 | 발광 제어 (전원측 / OLED측) | | |
| T7 | 애노드 리셋 (예시) | | |
| T8 | T1 온바이어스 스위치 (예시) | | |

### 예시 8T1C: 6T1C + T7 + T8

`pixel_8t1c.py`는 공개 문헌에서 흔한 두 기능을 **예시로** 붙였다. 특정 제조사 회로가 아니다.

```spice
Vobs vobs 0 5.0
NT7 vinit s1 nan mT7     ; 초기화 구간에 애노드를 VINIT로 리셋 (지난 프레임 OLED 잔류 전하 제거)
NT8 ns s1 vobs mT8       ; 초기화 구간에 T1 소스를 VOBS로 올려 T1을 강한 온바이어스 상태로 (히스테리시스 완화 목적)
```

구현 요령: 6T1C 넷리스트 생성 함수(`pixel.netlist`)를 그대로 부르고 `Cst` 줄 앞에 네 줄을 끼워 넣는다. **기존 코드를 복사해 고치지 않고 감싸기** 때문에 6T1C 결과가 바뀌지 않는다.

### 먼저 회로가 의도대로 도는지 본다 (중계조, 0 h)

| 구간 | v(애노드) | v(T1 소스) | v(게이트) | 애노드 전류 |
|---|---|---|---|---|
| 초기화 | **−3.50 V** (T7 리셋) | **5.00 V** (T8 온바이어스) | −3.50 V | 0 nA |
| 기록 | −3.37 V | 3.60 V (= Vdata) | 2.52 V | 0 nA |
| 발광 | 0.33 V | 4.59 V | 2.37 V | 237.5 nA |

초기화 구간에 두 TFT가 맡은 일을 했고, 기록 구간에 게이트가 Vdata − |Vth| 근처(2.52 V)에 앉았다.

### 결과: 거의 차이가 없다

| 계조 | 6T1C 0 h → 3000 h | 8T1C 0 h → 3000 h |
|---|---|---|
| 고계조 | 525.5 → 463.9 nA (88.3%) | 525.7 → 464.1 nA (88.3%) |
| 중계조 | 237.3 → 202.5 nA (85.3%) | 237.5 → 202.6 nA (85.3%) |
| 저계조 | 84.2 → 66.8 nA (79.3%) | 84.3 → 66.9 nA (79.3%) |

8T1C 중계조에서 한 TFT만 3000 h 열화: T1 −13.71%, T5 −0.76%, T6 −0.24%, T3 −0.20%, **T7 −0.00%, T8 −0.00%**.

## 비유: 제습기를 샀는데 방이 안 마른다

T7·T8은 **습기(OLED 잔류 전하, TFT 히스테리시스)를 잡으려고 산 제습기**다. 그런데 이 시뮬레이션의 방에는 **처음부터 습기가 없다.**

- 정답 모델 `ptft_true.va`에는 히스테리시스(트랩 충·방전 기억)가 없다.
- OLED 모델은 다이오드 + 0.3 pF 접합 용량뿐이고, 2프레임 정상상태 평균만 본다. 저계조 첫 프레임 응답·깜빡임은 보지 않는다.
- 그러니 제습기를 틀어도 방이 달라지지 않는다. **시뮬레이터가 틀린 게 아니라 질문이 모델에 없는 것이다.**

## 그래서 뭐

1. **"8T1C가 6T1C보다 열화에 강한가"를 이 모델로 답할 수 없다.** 답하려면 먼저 히스테리시스(시간 상수를 가진 Vth 이동)를 Verilog-A에 넣고, 프레임 단위 응답(첫 프레임 휘도, 계조 전환)을 측정 지표로 추가해야 한다.
2. **TFT를 더할 때마다 "이 TFT가 없으면 무엇이 나빠지는가"를 먼저 시뮬레이션으로 재현한다.** 재현이 안 되면 그 TFT의 열화 민감도도 의미가 없다.
3. **실측 8T1C로 옮길 때 가장 먼저 할 일**은 위 대응표 작성, 그다음 T1–T8 민감도(5장 방식)다. 민감도가 큰 TFT부터 측정 시간을 배정한다.

> **→ 9장에서 이 질문을 모델에 넣었다.** 트랩 상태 하나를 Verilog-A에 추가하고 지표를 계조 전환 직후 첫 프레임으로 바꾸자 T8(OBS)이 첫 프레임 오차를 줄였다. 다만 효과는 트랩 시정수에 크게 좌우됐고, 정상상태 유지율에는 이득이 없었다. [9장](ch09_hysteresis_8t1c.md)

## 비유가 깨지는 곳

1. 제습기 비유는 "효과 0"을 설명하지만, 실제 T7·T8의 효과가 **평균 전류에서는 원래 작고 과도 응답에서 크다**는 점까지는 담지 않는다. 지표 선택의 문제이기도 하다.
2. T7·T8 자체도 늙는다. 여기서는 T2와 같은 스트레스 지수(0.05)를 줬지만, 실제 구동에서 T8은 초기화 구간마다 큰 |Vgs|를 받을 수 있다. 바이어스는 회로에서 읽어 정한다.
3. T8의 VOBS = 5 V, T7·T8을 LTPS PMOS로 둔 것은 **예시용 선택**이다. 실제 설계값이 아니다.
