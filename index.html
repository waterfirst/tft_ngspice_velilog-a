00 · 오늘부터 실측 PMOS TR1 · NMOS TR3 · 상온/고온 · PBTS/NBTS

BTS I–V를 넣으면 8T1C 애노드 전류의 시간 변화가 30초 만에 나온다

측정 CSV → Vth·SS·μ 추출 → 온도 포함 열화식 → 화소 바이어스로 환산 → 8T1C 과도해석(ngspice + Verilog-A). TFT별 기여를 분리해 어느 소자를 더 재야 하는지 알려준다.

  • ① CSV 검사
  • ② 정전류 Vth · SS · μ
  • ③ SEF + Arrhenius (Ea)
  • ④ Vgs 파형 → PBTS/NBTS duty
  • ⑤ 8T1C 전류(t)
  • ⑥ T1 / T3 / T4 기여 분리

그림이 말하는 것

  • 지배 TFT는 계조와 회로 모델이 정한다. 전하기반 Cgs를 넣은 8T1C에서는 보상 스위치 T3가 저계조 전류를 가장 크게 바꿨다 (1 nA에서 −17%)
  • T4 음(−) 이동은 공개 전압 조건에선 거의 0. 깊은 off 상태라서다 — 실제 VGL·VINT·타이밍이 들어가야 방향이 확정된다
  • 외삽은 열화식에 따라 갈린다. SEF와 power law가 103 h 이후 벌어진다 → 스트레스 시간이 예측 한계를 정한다

그래서 요청드리는 측정

  • 스트레스 105 s 이상 — 예측 근거 한계 ≈ 최장 스트레스 × 100 (104 s면 약 280 h)
  • 온도 3점 — 2점이면 활성화에너지가 두 점 직선으로만 정해진다
  • 회복(recovery) · AC 스트레스 1–2조건 — DC→화소 환산 가정을 줄인다
  • C–V — 산화물 스위치의 킥백(비선형 Cgs) 보정
데이터는 로컬에서만 돌린다 — 측정 CSV와 결과는 외부로 나가지 않는다. 오늘 받은 데이터로 바로 첫 결과를 낼 수 있다.

02 · 어떻게 확인했나

실측 전에 채점이 가능한 시뮬레이션 환경부터 만들었다

정답을 아는 합성 세계를 만들고, 실제 연구 흐름(측정 → 추출 → 열화식 → 회로 → 전류)을 그 위에서 돌려 각 칸이 얼마나 틀리는지 따로 채점했다.

믿을 수 있게 만든 세 가지 장치

  • 정답 모델 ≠ 피팅 모델. "측정값"을 만든 모델과 추출에 쓴 모델이 다르다. 같으면 오차 0이 나와 답을 베낀 채점이 된다
  • 칸별 채점. 최종 전류 오차가 추출·열화식·회로 중 어디서 왔는지 나눠 본다
  • 재현 게이트. run_all.sh 한 번으로 모든 결과가 바이트 단위까지 같게 재생성된다

ngspice 45.2 + OpenVAF(Verilog-A) + Python. 교과서형 6T1C LTPO 화소와 예시 8T1C.

실측이 들어와도 같은 채점 틀을 그대로 쓴다 — 바뀌는 건 "정답" 자리뿐이다.

03 · 결론 ① 어느 TFT를 잴 것인가

전류 저하를 지배하는 건 스트레스가 가장 큰 T5가 아니라 구동 T1이다

왜 T5는 영향이 작나

T5·T6는 발광 중 선형영역 스위치다. |Vth|가 2 V 넘게 변해도 켜진 저항이 조금 늘 뿐이다.

왜 T1은 보상 회로가 있는데도 크나

게이트가 |Vth| 이동(0.857 V)을 61 mV 덜 따라갔다. 오버드라이브가 약 1 V라, 이상적이면 −3.5%(이동도 감소분)였을 손실이 −13.7%가 됐다.
측정 시간은 T1(LTPS PMOS)에 먼저 쓴다. 스트레스 순위로 측정 우선순위를 정하면 틀린다.

04 · 결론 ② AI를 어디에 둘 것인가

AI 단독은 처음 보는 계조에서 126% 틀렸고, 물리 결과를 보정만 한 Hybrid는 2.6%였다

AI 단독이 무너진 방식

저계조 화소 400개 전부에 약 180–215 nA를 답했다(정답 50–150 nA). 트리 모델은 학습 범위 밖에서 가장 가까운 칸의 값을 반복한다. 튜닝이 아니라 구조의 문제다.

Hybrid가 버틴 이유

경로는 물리(추출 + SPICE)가 정하고 AI는 log(정답 / 물리)만 학습한다. 학습 화소 100개일 때도 1.9%(GBM 5.0%, 물리 3.6%). 실측 화소가 비쌀수록 이 차이가 중요해진다.

8T1C 모집단(3300개)으로 반복해도 같았다

저계조에서 AI-GBM 127.5% vs Hybrid 2.6%. 단, 추출할 TFT가 6 → 8개로 늘자 시간 외삽의 꼬리 오차(P95)가 기존 흐름 29 → 39%, Hybrid 27 → 37%로 커졌다 — TFT가 많은 회로일수록 평균만 보면 안 된다.
AI는 물리를 대체하지 말고 잔차를 맡긴다. 성능은 반드시 "범위 안 / 시간 외삽 / 조건 외삽"을 나눠 보고한다.

05 · 8T1C 전체 파이프라인

8T1C를 끝까지 돌려도 수명과 예측 오차는 6T1C와 같았다 — T7·T8이 막는 현상이 모델에 없었다

고계조88.29%88.28%−1.17%
중계조85.33%85.33%−1.75%
저계조79.32%79.32%−4.01%

8개 TFT 모두 측정 → 추출 → 열화식 → 화소 채점

  • 전류 저하 기여(중계조, 그 TFT만 3000 h): T1 −13.71% · T5 −0.76% · T6 −0.24% · T3 −0.20% · T7·T8 0.00%
  • T7·T8 스트레스를 60 Hz 파형에서 측정: duty 0.0126(가정과 일치), |Vgs|는 T7 3.4 V · T8 11.8 V → 스트레스 지수 T7 1/8, T8 1.5배
  • 게이트: 기존 6개 TFT 추출값·넷리스트·0 h 전류가 6T1C 결과와 동일

T8(OBS)은 직전 화면의 트랩 기억(히스테리시스)을, T7은 OLED 잔류 전하를 지우는 장치다. 정답 모델에 히스테리시스가 없고 지표가 정상상태 평균이면 둘의 효과는 0으로 나온다. 예시 회로이며 제조사 회로가 아니다.

수명 지표로는 8T1C의 가치가 보이지 않는다. 그래서 트랩을 모델에 넣고, 지표를 계조 전환 직후 프레임으로 바꿨다.

06 · 결론 ③ 어떤 물리를 잴 것인가

트랩을 넣자 T8이 잔상을 줄였다 — 그러나 효과는 트랩 시정수 τ에 따라 −88%에서 −4%까지 달라졌다

무엇을 쟀나

  • TFT 모델에 트랩 상태 1개: 과거 vsg를 시정수 τ로 기억 → |Vth|에 반영
  • 저계조 또는 고계조에서 중계조로 전환한 첫 프레임의 전류 차이 = E1 (잔상 크기)
  • T7을 빼면 8T1C와 같고 T8을 빼면 6T1C와 같다 → 효과는 전부 T8

왜 τ가 정하나

OBS 펄스는 한 프레임에 100 µs뿐이다. τ가 그와 비슷하면 한 번에 트랩이 리셋되고(−88%), 10배 길면 일부만(−25%), 100배 길면 거의 못 지운다(−4%). VOBS를 4 → 6 V로 올려도 E1은 5.86 → 5.81%로 거의 그대로였다.

게이트: 트랩을 끄면 이전 결과 재현(오차 ≤ 6e-6) · τ 검증 63.2% · 시간 간격 20 µs vs 2 µs 차이 0.01% · 2회 실행 바이트 동일.

8T1C가 잔상에 얼마나 좋은지는 회로 시뮬레이션만으로 못 정한다. T1의 트랩 시정수 분포를 측정해야 정해진다.

"8T1C가 6T1C보다 좋은가"는 지표를 정하기 전엔 답이 없다. 수명·잔상·전류 오프셋을 따로 보고하고, 결론은 실타이밍으로 확인한다.

08 · 제안

그래서 첫 공동 작업은 시뮬레이션이 아니라 측정 프로토콜 합의다

첫 미팅에서 확인하고 싶은 다섯 가지

  1. T1(LTPS PMOS)의 stress / read / recovery 순서와 read 지연지연이 τ보다 길면 가역 성분이 데이터에 남지 않는다 → 결론 ③을 검증할 수 없다
  2. 가역 회복과 비가역 이동을 나눈 실험이 있는가비가역 → 열화식(수명), 가역 → 트랩 τ·세기(잔상). 섞으면 둘 다 틀린다
  3. 사용 중인 compact model과 기대 출력 1개우리 쪽 실행이 맞는지 판정할 유일한 기준
  4. 화소 전류의 정의 — 어느 노드, 어느 구간 평균, 어떤 타이밍정의가 다르면 같은 숫자가 다른 뜻이 된다 (가속 vs 실타이밍 1/4 착시)
  5. 모델 코드·데이터의 반출 범위공개 저장소에는 합성 예제만. 실측·넷리스트·모델 코드는 합의 범위 안에서만

우리가 가져가는 것

  • 검증 게이트가 달린 재현 가능한 파이프라인 (측정 → 추출 → 열화식 → 회로 → 전류)
  • TFT별 민감도·제거 실험 틀 — 실제 회로로 바로 다시 만들 수 있음
  • 물리 + AI 잔차 학습(Hybrid)과 3종 검증 (범위 안 / 시간 외삽 / 조건 외삽)
  • 트랩 파라미터를 recovery 곡선에서 뽑는 절차: 가역 진폭 / Δ → 세기, 회복 곡선 → τ, read 지연을 바꿔 0으로 외삽
  • 교재 12편 — 연구실 신규 인원 온보딩용

09 · 이 자료를 어디까지 믿을 것인가

방법은 검증했고, 숫자는 실측으로 다시 만들어야 한다

✓ 믿어도 되는 것

  • 파이프라인이 틀리면 드러나게 짜여 있다: 정답≠피팅 모델, 블라인드 시간, 칸별 채점
  • 게이트 통과: numpy 쌍둥이 식 일치, 트랩을 끄면 이전 결과 재현, τ 검증, 시간 간격 수렴
  • run_all.sh 재실행 시 모든 결과 바이트 동일
  • 경향의 방향: 전류 민감 TFT ≠ 고스트레스 TFT, 트리 모델의 외삽 실패, OBS 효과의 τ 의존

✗ 믿으면 안 되는 것

  • 구체적 수치 — 전부 합성, 시드 1개, 파라미터 세트 1개
  • 6T1C는 교과서형, 8T1C는 예시 하나. 특정 제조사 회로가 아니다
  • 트랩은 1개·충방전 대칭·모든 TFT 같은 세기, τ ≤ 10 ms만 확인
  • 스트레스 이력 고정(되먹임 없음), OLED는 다이오드 + 0.3 pF, 휘도 수명·온도 가속 제외
13.5× 이 작업의 일부 코드는 AI 코딩 에이전트가 썼다. T7·T8 스트레스 duty를 "시간점 개수"로 세서 0.082를 냈는데, ngspice는 스위칭 에지에 점을 몰아 찍는다. 시간 가중으로 바꾸면 0.0061(= 100 µs / 16.7 ms). 에러 없이 그럴듯한 숫자였고 손 검산 한 줄이 잡았다. 같은 코드에 측정값을 회로에 넣지 않는 버그도 있었다.
AI 도구는 속도를 주지만 검증 게이트는 사람이 설계해야 한다. 공동연구에서도 같은 원칙으로 간다.
